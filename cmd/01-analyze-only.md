# Agent 指令：只分析 Android 多模块项目，不修改代码

下面这段指令适合第一次让 Agent 接手项目时使用。  
它的目标是让 Agent 先理解项目结构，而不是直接修改文件。

---

## 可复制指令

```md
你是一个 Android 架构工程师，请先分析当前 Android 项目的多模块结构，但不要修改任何代码。

## 任务目标

请扫描当前项目，分析以下内容：

1. 当前有哪些模块
2. 哪些是壳工程
3. 哪些是业务模块
4. 哪些是支撑模块
5. 哪些是工具模块
6. 是否存在 API 模块
7. 当前模块依赖关系是否合理
8. 是否存在循环依赖或跨层依赖风险
9. 是否存在 app 壳工程过重的问题
10. 是否存在工具模块包含业务逻辑的问题
11. 是否存在支撑模块包含具体业务逻辑的问题

## 检查范围

请重点查看：

- settings.gradle / settings.gradle.kts
- 根目录 build.gradle / build.gradle.kts
- app 模块
- business 目录
- support 目录
- libs 目录
- api 目录
- 各模块 build.gradle / build.gradle.kts
- 各模块 README.md，如果存在

## 输出要求

请输出一份分析报告，包含：

- 当前模块清单
- 模块分类建议
- 当前依赖关系总结
- 发现的问题
- 推荐调整方案
- 推荐新增的文档文件
- 后续执行计划

## 约束条件

- 本轮只分析，不修改代码。
- 不创建文件。
- 不删除文件。
- 不调整 Gradle 配置。
- 不移动任何源码。
- 如果判断不确定，请明确标注“不确定，需要人工确认”。
- 如果模块职责无法从目录名或代码中明确判断，请标记为“待补充”，不要编造。

## 输出格式

请使用 Markdown 格式输出。
```

---

## 使用建议

这个指令适合用于：

- 第一次接入旧项目
- 项目模块较多但缺少文档
- 想让 Agent 先出一份架构分析报告
- 担心 Agent 直接修改代码带来风险

建议先执行这一条，确认 Agent 对项目理解正确后，再执行文档生成指令。
